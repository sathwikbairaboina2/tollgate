# Tollgate v0.1 spec (2026-10-03)

Status: approved by brief (no brainstorming Q&A; decisions recorded as ADRs in `docs/adr/`).

## One line

An OpenAI-compatible LLM gateway in Go where a deterministic core owns keys, money and limits:
the model upstream proposes tokens, the gateway decides whether the request may be sent at all.

## Thesis

"The model proposes, the deterministic core disposes." Every declared limit (budget, rate limit,
fallback policy, per-request output cap) is enforced *before* bytes leave for an upstream, and each
one has a test that proves enforcement against a fake upstream.

## Scope (v0.1)

In:
- `POST /v1/chat/completions`, non-streaming JSON and streaming SSE, OpenAI wire format in and out.
- `GET /healthz`, `GET /metrics` (Prometheus text format).
- Virtual API keys from YAML (`Authorization: Bearer <key>`). Upstream secrets come from env vars
  named in config (`api_key_env`), never from the YAML itself.
- Providers: any OpenAI-compatible upstream (`base_url` + optional key), e.g. OpenAI, Groq,
  vLLM, local Ollama at `http://localhost:11434/v1`.
- Routing: a `routes` table maps a public model name to an ordered list of `{provider, model}`
  targets. Fallback to the next target on transport error, HTTP 429, or HTTP 5xx. No fallback on
  other 4xx (the request is wrong, not the upstream). For streams, fallback is only possible before
  the first byte is written to the client (decided on the upstream status line).
- Per-key budgets in tokens and/or USD, enforced by **reservation**: before forwarding, the gateway
  reserves the worst-case cost (estimated prompt tokens + `max_tokens`) and rejects with HTTP 402 if
  the reservation would exceed the remaining budget. After the response, the reservation is settled
  to actual usage (from upstream `usage`, or estimated for streams without usage).
  If a request has no `max_tokens`, or asks for more than the key's `max_output_tokens`, the gateway
  rewrites it to the cap, so the worst case is always bounded.
- Per-key token-bucket rate limit (`requests_per_second`, `burst`); over-limit returns HTTP 429 with
  `Retry-After`.
- Exact-match response cache for non-streaming requests: key = SHA-256 of canonical JSON of the
  request body (minus `stream`, `user`) plus resolved route. In-memory LRU with TTL behind a `Cache`
  interface (semantic cache is a later implementation of that interface). Cache hits cost 0 budget
  but still count against the rate limit.
- OpenTelemetry spans per request using GenAI semantic conventions (`gen_ai.operation.name`,
  `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.request.max_tokens`,
  `gen_ai.response.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`,
  `gen_ai.response.finish_reasons`) plus `tollgate.*` attributes (key id, cache hit, attempts).
  OTLP/HTTP export when `OTEL_EXPORTER_OTLP_ENDPOINT` is set; no-op otherwise.
- Prometheus metrics: requests, tokens, cost, cache hits, fallbacks, rejections by reason,
  upstream latency histogram.
- `bench/`: replays a fixed request set through the gateway against an in-process fake upstream and
  reports added p50/p99 latency and cache hit rate / cost saved. README numbers come from real runs.
- Dockerfile (multi-stage, distroless), Makefile with docker-only targets (Go is not required on host).
- `docker-compose.yml` demo stack: gateway (:8787), deterministic fake upstream, Prometheus (:9090)
  scraping `/metrics`, Jaeger (:16686) receiving OTLP, and a `bench` profile. Everything runs in
  Docker. Tollgate uses no AWS, so there is no LocalStack.
- Prompt-token bound = byte length of JSON-encoded messages + tools + 8 (see ADR 0001). Config
  refuses to load if a key has a USD budget and a routed model has no price.

Out (stretch, see handoff): Anthropic adapter, semantic cache, persistent/shared budget store
(Redis), budget reset periods, Helm chart, streaming cache replay, tool-call-aware token counting,
admin API, per-route rate limits.

## Error contract

OpenAI-shaped error body: `{"error":{"message":..., "type":..., "code":...}}`.

| Condition | Status | code |
|---|---|---|
| missing/unknown key | 401 | `invalid_api_key` |
| malformed body / missing model / no messages | 400 | `invalid_request` |
| unknown model (no route) | 404 | `model_not_found` |
| rate limited | 429 + `Retry-After` | `rate_limited` |
| budget would be exceeded | 402 | `budget_exceeded` |
| all targets failed (retryable) | 502 | `upstream_unavailable` |
| non-retryable upstream 4xx | upstream status, upstream body passed through | — |

## Config (YAML)

```yaml
listen: ":8787"
providers:
  - name: ollama
    base_url: http://localhost:11434/v1
  - name: openai
    base_url: https://api.openai.com/v1
    api_key_env: OPENAI_API_KEY
    timeout: 60s
routes:
  - model: chat-default
    targets:
      - { provider: openai, model: gpt-4o-mini }
      - { provider: ollama, model: llama3.2 }
pricing:            # USD per 1M tokens, keyed by upstream model
  gpt-4o-mini: { input: 0.15, output: 0.60 }
keys:
  - id: team-a
    key_env: TOLLGATE_KEY_TEAM_A   # or `key:` literal for local demos only
    budget: { usd: 5.00, tokens: 2000000 }
    rate_limit: { requests_per_second: 5, burst: 10 }
    max_output_tokens: 1024
cache:
  enabled: true
  max_entries: 10000
  ttl: 10m
```

## Acceptance

1. `make test` (dockerised `go test -race ./...`) passes with no network beyond module download.
2. One test per declared limit: budget (tokens and USD, including concurrent reservations),
   rate limit, output cap rewrite, fallback on 5xx/429/transport error, no fallback on 400.
3. Streaming test: SSE chunks are relayed in order and usage is settled.
4. `make bench` produces numbers; README quotes them verbatim.
